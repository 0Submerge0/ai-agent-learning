# V3 文件整理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 agent 能整理文件（列目录 / 读文件 / 移动 / 建目录），但**所有文件操作被限制在 `workspace\` 内**，且**写操作前必须用户按 `y` 确认**。

**Architecture:** 第一次抽 `agent\` 包——V2 单文件已经 200 行，再往里塞 4 个工具 + 沙箱会失控。拆成三个模块：`client.py`（与模型通信）、`tools.py`（工具定义+实现+分发）、`sandbox.py`（路径校验）。新入口 `src/v3_files.py` 只保留 REPL 与工具循环。

**Tech Stack:** Python 3.14（uv）、`requests`、标准库 `pathlib`/`json`。

**Spec:** `docs/superpowers/specs/2026-10-29-ark-agent-design.md`（5.4 安全边界为硬约束）

## Global Constraints

- 接口、模型 ID 不变：`deepseek-v4-1-flash-260910`
- 依赖上限：只有 `requests`
- **沙箱不可协商**：路径先 `resolve()` 再 `is_relative_to(WORKSPACE)`，拒绝 `..` 逃逸与符号链接穿透
- **写操作不可协商**：`move_file`/`mkdir` 默认只打印计划，用户输入 `y` 才执行
- 不提供 `run_shell`、不提供删除
- `MAX_ITERATIONS = 8`（多步文件操作比聊天需要更多轮）
- V2 的既有能力全部保留：多轮记忆、`/clear`、`/exit`、`ModelError` 重试、思考块回填

## Review Focus

1. **越界必须被拒**：`../src`、`D:\zjy\AI\src\..\src\v2_repl.py`、workspace 内指向外部的符号链接，全部要报错而不是照做。
2. **写操作默认不生效**：用户答 `n`（或直接回车 / EOF）时，磁盘不能有任何变化。
3. **拒绝后模型能继续**：用户拒绝一次，工具返回「用户拒绝了」，模型要能改口或询问，程序不崩。
4. **目标已存在不覆盖**：`move_file` 遇到同名目标应拒绝，避免静默覆盖。
5. **工具结果仍进历史**：V2 的记忆特性不能被拆包破坏。

### Task 1: 沙箱模块

**Files:**
- Create: `src/agent/__init__.py`
- Create: `src/agent/sandbox.py`

**Interfaces:**
- Produces: `WORKSPACE: Path`；`safe_path(path: str, must_exist: bool = False) -> Path`；`rel(p: Path) -> str`

- [ ] **Step 1: 写 `__init__.py`**（一句话 docstring）

- [ ] **Step 2: 写 `sandbox.py`**

`WORKSPACE` 用 `Path(__file__).resolve().parent.parent.parent / "workspace"` 定位（相对文件自身，不写死盘符）。`safe_path` 规则：相对路径按 workspace 解释；`resolve()` 后必须 `is_relative_to(base)`，否则 `raise ValueError`；`must_exist=True` 时再检查存在。`rel()` 把绝对路径转成相对 workspace 的 `a/b` 形式，用于输出。

- [ ] **Step 3: 本地验证**

Run: `uv run python -c "import sys; sys.path.insert(0,'src'); from agent.sandbox import safe_path, WORKSPACE; print(WORKSPACE); safe_path('../src')"`

Expected: 打印 workspace 绝对路径；第二句抛 `ValueError`（越界）。

### Task 2: 工具定义与实现

**Files:**
- Create: `src/agent/tools.py`

**Interfaces:**
- Consumes: Task 1 的 `safe_path` / `rel`
- Produces: `TOOLS: list[dict]`；`WRITE_TOOLS: set[str]`；`run_tool(name, args, ask=None) -> str`；四个工具函数

- [ ] **Step 1: 写四个工具**

- `list_dir(path=".")`：只读，列 workspace 内目录，最多 50 条，条目显示相对路径与 `<dir>`/字节数。
- `read_file(path, max_chars=4000)`：只读，UTF-8 读文本，超长截断并提示。
- `mkdir(path)`：写，创建目录（父目录一并创建）。
- `move_file(src, dst)`：写，移动/改名；`src` 必须存在，`dst` 已存在则拒绝覆盖，自动建父目录。

四个函数内部一律先 `safe_path(...)`，把越界变成 `ValueError`。

- [ ] **Step 2: 写 `TOOLS` 与分发**

`TOOLS` 四个 schema，参数名与函数签名一致。`run_tool` 用 dict 分发；未知工具返回中文提示；**写工具**先打印 `[计划] ...`，再 `ask("执行? (y/N) ")`，只有回答 `y` 才调用函数，否则返回「用户拒绝了这次操作，未执行。」。`ask` 默认 `input`，测试时可注入。任何异常都转成文字返回，不抛。

- [ ] **Step 3: 本地验证（不调模型）**

Run: 用注入 `ask` 的方式测四条——`ask` 返回 `n` 时 mkdir 不生效；`y` 时生效；`move_file` 越界报错；`move_file` 目标已存在报错。

Expected: 四条都符合预期，程序不抛未捕获异常。

### Task 5: V3 讲义

**Files:**
- Create: `docs/notes/v3.md`

- [ ] **Step 1: 写讲义**

三件事：
1. **沙箱是「能力的边界」，不是「代码的礼貌」**——模型能做什么 = 工具能做什么；路径校验把「越界」从「祈祷模型自觉」变成「代码强制」。
2. **写操作必须有人把关（human-in-the-loop）**——模型可以提议，但不能单方面执行；`y` 是人类保留的最后一道开关。
3. **抽象是被需求逼出来的**——V2 单文件 200 行还能读，V3 再塞 4 个工具 + 沙箱就失控了，这时拆包才有意义。
