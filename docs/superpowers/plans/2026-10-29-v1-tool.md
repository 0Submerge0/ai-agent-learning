# V1 工具调用 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让模型自己决定调用一个工具，程序执行它、把结果喂回去，模型再接着说——把 agent 的闭环走通一次。

**Architecture:** 新文件 `src/v1_tool.py`，**从 `v0_chat.py` 复制后改**，不抽公共模块（刻意保留重复，便于与前版并排对照）。新增两样东西：工具定义（JSON Schema）与一个 `while` 循环。工具先用只读的 `list_dir`。

**Tech Stack:** Python 3.14（uv）、`requests`、标准库 `os`/`sys`/`json`/`pathlib`。

**Spec:** `docs/superpowers/specs/2026-10-29-ark-agent-design.md`

## Global Constraints

- 接口、请求头、模型 ID 不变，沿用 V0：`deepseek-v4-1-flash-260910`
- 依赖上限：只有 `requests`
- 单文件 ~100 行（不含空行注释），不引入包结构 `agent\`（那是 V2）
- 工具本版**只读**，不做沙箱（沙箱是 V3 的教学点，提前做会削弱 V3）
- 模型响应里的 `content` 数组必须**原样**回填（含 `thinking` 块及其 `signature`），否则接口会报错
- 循环必须有上限 `MAX_ITERATIONS = 5`，防止模型无限调用工具烧钱
- 失败信息必须可读：工具抛异常时，把异常文本作为 `tool_result` 回给模型，而不是让程序崩

## Review Focus

1. **thinking 块回填**——少回填或改写 `signature` 会导致下一轮请求失败；必须整块原样 append。
2. **`tool_use_id` 对不上**——`tool_result` 的 `tool_use_id` 必须逐字等于模型给的 `id`，错一个字符就报错。
3. **模型一次返回多个 `tool_use`**——不能只处理第一个；要全部执行并把所有 `tool_result` 放进同一条 user 消息。
4. **工具名不存在**（模型幻觉，或我们改错了 `TOOLS` 里的 name）——要回一条「没有这个工具」的 `tool_result` 让模型自己纠正，而不是抛 `KeyError`。
5. **`stop_reason` 为 `max_tokens` 时也含 `tool_use`**——截断的工具参数可能不完整，不能盲目执行，应提示模型重说。

### Task 1: 工具定义与执行

**Files:**
- Create: `src/v1_tool.py`（先只含常量、工具定义、`list_dir`、`run_tool`）

**Interfaces:**
- Consumes: 无（本任务自包含）
- Produces:
  - `TOOLS: list[dict]` — Anthropic 格式的工具定义数组
  - `list_dir(path: str) -> str` — 返回目录条目文本，最多 50 条
  - `run_tool(name: str, args: dict) -> str` — 按名字分发；未知工具/异常都返回可读的错误文本，不抛

- [ ] **Step 1: 复制 V0 作为起点**

```powershell
Copy-Item src\v0_chat.py src\v1_tool.py
```

保留常量区与 `chat` 的错误处理；本任务先不动 `chat`。

- [ ] **Step 2: 写 `TOOLS` 与 `list_dir`、`run_tool`**

`TOOLS` 里只放一个工具，`name` 为 `list_dir`，`input_schema` 要求必填 `path`（`{"type":"object","properties":{"path":{"type":"string"}},"required":["path"]}`）。`description` 要写清「列目录内容，返回文件名与大小」。

`list_dir` 用 `pathlib.Path` 读目录，按字母序，每条输出 `名字  <大小>`；目录标为 `<dir>`；超过 50 条时末尾加一行「（已截断，共 N 条）」。路径不存在或不是目录，`raise ValueError` 带中文说明。

`run_tool` 用 `dict` 做分发表（`{"list_dir": list_dir}`），未知名字返回 `"没有名为 X 的工具，可用：..."`；捕获 `Exception` 返回 `"工具执行失败：" + str(e)`。

- [ ] **Step 3: 本地验证（不调模型）**

Run: `uv run python -c "import sys; sys.path.insert(0,'src'); import v1_tool as t; print(t.run_tool('list_dir', {'path': '.'}))"`

Expected: 打印出 `D:\zjy\AI` 的条目；再试 `t.run_tool('nope', {})` 应返回中文错误文本而不是抛异常。

### Task 2: 智能体循环

**Files:**
- Modify: `src/v1_tool.py`（把 `chat` 改成 `run_agent`，接上循环）

**Interfaces:**
- Consumes: Task 1 的 `TOOLS`、`run_tool`
- Produces: `call_model(messages: list, tools: list) -> dict`；`run_agent(question: str) -> None`

- [ ] **Step 1: 抽出 `call_model`**

把 V0 `chat` 里的「发请求 + 判状态码 + 解析 JSON」整段挪进 `call_model(messages, tools)`，返回 `data`。key 清洗、异常分流、JSON 保护原样保留。

- [ ] **Step 2: 写循环**

`run_agent` 维护 `messages`，`for _ in range(MAX_ITERATIONS)`：
1. `data = call_model(messages, TOOLS)`
2. `messages.append({"role": "assistant", "content": data["content"]})` —— **原样**，不筛选
3. 若 `stop_reason == "tool_use"` 且 `stop_reason != "max_tokens"`：收集所有 `tool_use` 块，逐个 `run_tool`，拼成 `tool_result` 列表，作为**一条** user 消息 append，继续循环
4. 否则打印文本并 `return`
循环走完仍没结果，打印「超过最大轮数」。

- [ ] **Step 3: 正常路径验证**

Run: `uv run python src/v1_tool.py "看看当前目录里有什么文件"`

Expected: 先打印一行「[调用工具] list_dir {...}」（调试输出），再打印模型基于目录内容的中文总结，最后是用量。

- [ ] **Step 4: 故意失败演示 A —— 路径不存在**

Run: `uv run python src/v1_tool.py "列出 not-exist-dir 里的东西"`

Expected: 工具返回错误文本 → 模型据此说明「目录不存在」，**程序不崩**。

- [ ] **Step 5: 故意失败演示 B —— 工具名写错**

临时把 `TOOLS[0]["name"]` 改成 `list_dirr`（执行时保持一致），跑 Step 3 的命令。

Expected: `run_tool` 返回「没有名为 list_dirr 的工具」，模型因此在回答里说明工具不可用，程序不崩。看完改回。

- [ ] **Step 6: 提交**

```bash
git add src/v1_tool.py
git commit -m "feat(v1): 工具调用闭环"
```

### Task 3: V1 讲义

**Files:**
- Create: `docs/notes/v1.md`

**Interfaces:**
- Consumes: Task 2 的真实输出
- Produces: 讲义，结构同 `v0.md`（做了什么 / 逐块讲 / 三件事 / 改一改试试 / 复述题）

- [ ] **Step 1: 写讲义**

必须讲清的三个「三件事」：
1. **模型不会执行任何东西**——它只是输出「我想调用 list_dir，参数是 …」，执行权在我们手里。这是 agent 与「聊天」的分界线。
2. **`tool_result` 是靠 `tool_use_id` 配对回去的**，不是靠顺序。类比：RPC 的 request id。
3. **`thinking` 块必须原样回填**——实测过，改写或丢弃会导致下一轮失败。

必须包含的对比表：V0 的 `content` 只有 `text`；V1 会出现 `tool_use`，且 `stop_reason` 从 `end_turn` 变成 `tool_use`。

- [ ] **Step 2: 按讲义逐条重跑命令，核对行号与输出**

- [ ] **Step 3: 提交**

```bash
git add docs/notes/v1.md
```
