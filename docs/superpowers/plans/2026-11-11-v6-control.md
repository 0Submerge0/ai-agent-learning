# V6 计划可修改 + 人工接管 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** V5 的计划批准后就锁死了：模型把任务标成 `failed`，你只能干看着；预算/轮次把任务拦腰截断，你只能手打「继续」。V6 把计划交还给人——能跳过、重试、改名、加任务、删任务，改完 `/go` 接着跑；同时修掉 V5 实测暴露的两个坑（单轮冲爆预算、轮次装不下任务）。

**Architecture:** 新增入口 `src/v6_control.py`，复用 `v5_planner` 的 `planning_phase` / `approve_plan` / `execution_phase` / `load_resume` / `save_session`，只加一层**命令层**。`agent/plan.py` 增加 5 个人工操作方法 + 一个统计方法。`v5_planner.execution_phase` 增加两个**可选**参数（轮次上限、软着陆），默认值下 V5 行为一字不变。

**Tech Stack:** Python 3.14（uv）、`requests`、标准库。

**Spec:** `docs/superpowers/specs/2026-10-29-ark-agent-design.md`；V5 讲义 §4（踩坑）、§7（V5 没做的事）

## Global Constraints

- **V5 入口行为不变**：`execution_phase` 的新参数都有默认值，不传时走原逻辑
- **模型侧工具不变**：执行阶段仍然只有 6 个写工具 + `update_task`；模型**不能**改计划结构
- **改计划只由人发起**：命令层不在模型工具清单里
- 沙箱、两道闸门、预算、日志、存档全部保留
- 计划仍最多 12 个任务；状态仍是那 5 个
- 依赖仍只有 `requests`

## Review Focus

1. **接管真的生效**：`/skip` 后进度立刻变，`/go` 时模型看到的是**改过的**计划（system prompt 每轮重新渲染）
2. **改动立即落盘**：改完直接 `/exit`，`/resume` 回来还是改后的样子
3. **编号不悬空**：`/rm` 后任务重新编号 1..N，`/plan` 和模型看到的一致
4. **软着陆不是硬停**：剩余预算不够下一轮时，先保存再停，不丢现场
5. **V5 不受影响**：`uv run python src/v5_planner.py` 行为与提交时一致

### Task 1: `Plan` 的人工操作

**Files:**
- Modify: `src/agent/plan.py`

**Interfaces:**
- Produces: `Plan.skip(task_id)`；`Plan.retry(task_id)`；`Plan.rename(task_id, title)`；`Plan.add(title)`；`Plan.remove(task_id)`；`Plan.counts()`；`Plan.find(task_id)`

- [ ] **Step 1: 加 `find` 与 `counts`**

`find` 返回 `Task` 或抛 `ValueError`（错误信息带总数）。`counts()` 返回 `{"done":n,"skipped":n,"failed":n,"pending":n,"in_progress":n}`，用来在收口时打「6 done / 1 failed」而不是笼统的「还有 1 个未完成」。

- [ ] **Step 2: 加 5 个方法**

- `skip(id)`：只允许从 `pending / in_progress / failed` 跳到 `skipped`；已经是 `done` 的报错（「任务 3 已完成，跳过没有意义」）
- `retry(id)`：任何非 `pending` 状态重置为 `pending`，并清空 `note`
- `rename(id, title)`：标题去空白，空标题报错；不动状态
- `add(title)`：追加到末尾，新 id = 当前最大 id + 1，超过 12 报错
- `remove(id)`：删掉后**重新编号** 1..N（说明写在 docstring 里：编号会变，因为人读的是序号）

- [ ] **Step 3: 本地验证**

Run: 5 个方法各跑一次 + 4 个非法输入（skip 已完成、retry 不存在的 id、rename 空标题、add 到 13 个）。确认 `render()` 与 `counts()` 同步。

### Task 2: 执行阶段的两个修复

**Files:**
- Modify: `src/v5_planner.py`

- [ ] **Step 1: `execution_phase` 加参数**

```python
def execution_phase(..., ask=None, max_iterations=None, soft_landing=False):
    limit = max_iterations or EXECUTION_MAX_ITERATIONS
    for _ in range(limit):
        ...
```

默认 `None / False` → 与 V5 完全一致。

- [ ] **Step 2: 软着陆**

循环内记录上一轮实际花费（`input_tokens + output_tokens`）。当 `soft_landing` 为真、且 `budget.remaining < 上一轮花费` 时，打印「剩余预算低于上一轮成本，提前收尾」，`save_session` 后返回 `executing`。

- [ ] **Step 3: 收口改用 `counts()`**

结束时打印分项：`6 done / 1 failed / 0 pending`，并保留 `is_complete` 的严格判定（`failed` 不算完成）。

- [ ] **Step 4: 回归**

Run: `uv run python src/v5_planner.py`，`/plan`、`/exit` 正常；`execution_phase` 不传新参数时行为不变（对比 V5 代码路径）。

### Task 3: 命令层（`src/v6_control.py`）

**Interfaces:**
- Consumes: `v5_planner` 的 `planning_phase` / `approve_plan` / `execution_phase` / `load_resume` / `save_session`；`agent.plan.Plan`

- [ ] **Step 1: 命令解析**

`/skip N`、`/retry N`、`/edit N 标题`、`/add 标题`、`/rm N`、`/plan`、`/go`、`/resume`、`/clear`、`/exit`。
统一走一个 `handle_command(line, plan, store, goal, phase, budget, log) -> str`，返回新的 phase。
所有错误（缺参数、非数字、无计划）都返回可读中文，不抛异常。

- [ ] **Step 2: 每次改动立即存档**

改完立刻 `save_session(...)`，并把 `phase` 从 `done` 拉回 `executing`（因为计划又有活了）。

- [ ] **Step 3: `/go`**

`plan` 存在且未完成 → 调 `execution_phase`，轮次上限 `max(16, 3 * 剩余任务数 + 4)`，`soft_landing=True`。

- [ ] **Step 4: 兼容「继续」**

V5 的习惯保留：输入「继续」等同 `/go`。

- [ ] **Step 5: 本地验证（不调模型）**

合成存档 → `/skip` `/retry` `/add` `/edit` `/rm` `/plan` → 读存档文件核对；无计划时每条命令都给友好提示。
