# 学习计划：从「代码跑通」到「能讲清、能面试」

> 起点：V0–V6 全部交付，源码已加中文注解（16 个文件，AST 校验通过）。
> 终点：能独立讲清 agent 的每个设计选择，并有可展示的作品。
> 总时长估算：4–6 周，每天 1–2 小时。

---

## 执行版：碎片时间安排（当前适用）

### 前提（2026-11-12 更新）

| 事实 | 影响 |
|---|---|
| 代码是 AI 写的，本人未手写 | 缺「定位 / 预测 / 取舍」三种手感，验收之前不能加新功能 |
| 无 Python 基础（本职 Java） | 但只需补本项目的 40 个构造，不需要系统学 |
| 只有碎片时间 | 不排「每天 1 小时连续」，改排 15–30 分钟单元 |

**结论：阶段 0 之后不能直接进入阶段 2（加功能），必须先插入「手感建立」环节。**
理由见 `docs/notes/agent-architecture.md` 与对话记录：
非异常失败（静默错误）只能靠「撞过」识别，读代码无法获得。

### 顺带说清楚：Python 要不要先学

不要。执行顺序是 **A3（30 分钟速览）→ B1（边写边查）**，不是「先学完 Python」。

- 这个项目只用了 Python 的一小部分（见 `glossary.md` L5 的「没用的」那一列）
- 真正会绊住的是**行为差异**而不是语法：真值判断、`and/or` 返回操作数、
  可变默认参数、标注不强制、`dict` 缺键、循环变量外泄、缩进即语法
- 这 7 条用「改一处、看结果」学最快，不要看书

# 阶段 1：验收（0 token）

**目的**：找出「以为懂了其实没懂」的地方。不做这步，后面的练习会变成抄代码。

## 1.1 复述题（口述，不用写）

### 基础（必须全过）

1. `messages` 数组里，`tool_result` 为什么是 `user` 角色？
2. 模型服务端不保存对话，那它为什么能「记住」你上一句说的话？
3. `/clear` 到底清掉了什么？什么没被清掉？
4. `tools` 那段 JSON 是给谁看的？模型能看到 `list_dir` 的实现吗？
5. 为什么说「模型不能干坏事」这件事，本质是「`run_tool` 里没有那个函数」？

### 进阶（至少过一半）

6. 为什么先 `resolve()` 再 `is_relative_to()`？反过来会怎样？
7. 确认闸门（`执行? y/N`）为什么默认是「不执行」？
8. `plan.is_complete` 为什么不算 `failed`？这样设计的代价是什么？
9. 计划审批和写操作确认，为什么不能合成一道闸门？
10. `session_store.save` 为什么先写 `.tmp` 再 `replace`？

### 难点（能答 2 个就算过）

11. `execution_phase` 有 5 个出口，分别在哪？哪个能返回 `done`？
12. `/retry 4` 之后进度还是 `3/6`，`/skip 6` 之后变成 `4/6`，为什么？
13. 第一次 `/go` 时模型为什么罢工？它看到的历史和你看到的状态差在哪？
14. 接管消息为什么用 user 消息，而不是写进 system prompt？
15. V5 用两套工具清单（阶段隔离），Manus 建议「工具清单别变、靠状态限制」。两边各自在优化什么？

## 1.2 指代码（5 题）

每题给一个**具体行号**，不能翻讲义。

# 阶段 2：三个改码练习（< 5k token）

## 练习 1：把 V1/V2 的重复代码收掉

**现状**：同一段「读 key + 发请求」抄了三遍

```
v0_chat.py   第 64-118 行   内联
v1_tool.py   第 132-186 行  内联
v2_repl.py   第 111-166 行  内联
client.py    第 45-110 行   公共版（V3 起复用）
```

**做什么**：把 V1、V2 改成 `from agent.client import call_model, extract_text`，删掉自己那份。

**会学到**：
- 为什么是「第三次重复」才该抽象（Rule of Three）
- `ModelError` 和 `sys.exit` 的区别：一个能让 REPL 继续，一个直接杀进程
- 为什么 401 不重试、超时重试

**验收**：
- `uv run python src/v1_tool.py "看看当前目录"` 能跑通
- 两个文件各少 40–50 行
- `git diff` 里只有「删掉 + import」

**风险**：低。V1/V2 不涉及存档，改坏了 git 能退回。

## 练习 2：加一个 `copy_file` 工具

**做什么**：照着 `move_file` 抄一个复制，用到 V4。

**你会撞到一件事**：加一个工具不是改一个地方，是**五处**。

| 位置 | 改什么 | 漏了会怎样 |
|---|---|---|
| `agent/tools.py` 第 51 行前 | 加 JSON schema | 模型不知道有这个工具 |
| `agent/tools.py` 第 96 行前 | 加实现函数 | 调了报「没有这个工具」 |
| `agent/tools.py` `WRITE_TOOLS` | 加进集合 | **绕过确认闸门**（最危险） |
| `agent/tools.py` `describe_write` | 加分支 | 确认提示是空的，用户盲签 |
| `agent/tools.py` `run_tool` registry | 加一行 | 分发不到 |
| `agent/tools_v4.py` `run_tool` registry | 加一行 | V4 用不了 |

**验收**：
- 让 V4 复制一个文件，必须弹 `执行? (y/N)`
- 答 `n` 时磁盘哈希零变化
- 目标已存在时拒绝覆盖

**会学到**：「说明书」和「实现」是两套东西，必须同时改。这是 agent 开发最容易漏的地方。

## 练习 3：故意改坏三处，看它怎么炸

| 改坏哪里 | 预期现象 | 看完改回来 |
|---|---|---|
| `plan.py` `is_complete` 改成 `any(...)` | 一个任务完成就说「全部完成」 | ☐ |
| `sandbox.py` 删掉 `is_relative_to` 检查 | `../` 能逃出 workspace | ☐ |
| `client.py` 删掉 `.strip()` | key 带空格 → 401 | ☐ |

**会学到**：错误处理不是装饰，是边界。之前是我制造失败给你看，这次你自己制造。

**验收**：每处都能说出「哪一行负责挡住它」。

# 阶段 3：加一个新能力（三选一）

三个都不加版本号，是在 V6 上加一层。

## 选项 A：上下文裁剪（推荐）

**问题**：`messages` 只增不减。V6 演示 15 条消息就 5.7 万 token，真用一天必爆。

**做什么**：当 `messages` 超过阈值（比如 20 条），把最早的一批压成一条摘要，保留最近 N 轮。

**要回答的判断题**（这才是价值所在）：
- 压掉哪些？`tool_result` 能不能删？（删了历史会不合法）
- 摘要里必须保留什么？（目标、已完成的事、失败过的事）
- 什么时候压？（到阈值就压，还是每轮都压）
- 压完怎么保证模型不重复干已做过的事？

**规模**：约 40 行，一个 `agent/context.py`。

**验收**：跑一个 12 个文件的任务，全程 `messages` 不超过 20 条，任务仍然 100% 完成。

## 选项 B：最小评测

**问题**：改一次提示词，只能跑一遍肉眼看。

**做什么**：3 个固定任务 + 断言（文件在哪、报告有没有、预算多少），改提示词前后各跑一次对比。

**规模**：约 50 行。

**验收**：能输出一张对比表：哪次改动让通过率从 2/3 变成 3/3。

**评价**：收益最长期，但最枯燥。等你开始频繁调提示词时再上。

## 选项 C：流式输出

**做什么**：`stream=True`，逐块打印，处理 SSE 格式。

**规模**：约 60 行。

**验收**：终端逐字出现，而不是等 10 秒一次性吐完。

**评价**：体验提升明显，但对「理解 agent」帮助最小。学的是 SSE 协议，不是 agent。

# 阶段 4：求职向（2–3 周）

**这一阶段的目标不是「学更多」，是「有东西可展示」。**

## 优先级排序（按求职回报）

### 4.1 把 V6 包成 HTTP 服务（最高优先）

**为什么**：面试官看简历时不关心「你实现了一个 while 循环」，关心「你能把它做成别人能用的东西」。

**做什么**：
- FastAPI 包一层：`POST /sessions` 建会话、`POST /sessions/{id}/messages` 发消息、`GET /sessions/{id}` 查状态
- 把「确认闸门」从 `input()` 改成「返回待确认动作，等客户端再调 `/confirm`」
- 会话状态从内存搬到 Redis 或 sqlite
- Dockerfile

**规模**：约 300 行。

**会学到**：agent 从「本地脚本」到「服务」要改什么——最大的变化是**不能阻塞等人输入**，确认闸门要变成异步状态。

**这一条最能写进简历。**

### 4.2 最小评测（其次）

10 个固定任务 + 自动断言，每次改提示词跑一遍。

**为什么**：这是「工程能力」和「玩具」的分界线。面试问「你怎么知道改动变好了」，没这个只能答「我感觉」。

**规模**：约 200 行 + 10 个任务定义。

### 4.3 最小 RAG（第三）

读文档 → 切块 → 检索（先用 BM25 或简单的关键词，不必上向量库）→ 塞进上下文。

**为什么**：招聘 JD 里 RAG 出现频率极高。但**不要一上来就上向量数据库**，先用最简单的检索证明「你懂原理」。

**规模**：约 150 行。

**注意**：这才是设计文档里明确列为「非目标」的那一项。做它的理由是求职，不是项目完整性。

## 明确不做

| 不做 | 理由 |
|---|---|
| 多 agent 协作 | 最容易做成花架子，你现在连单 agent 都没读透 |
| Web UI | 除非服务化需要最小页面 |
| 向量库调优 | 先证明懂原理，再谈调优 |
| 用 LangChain 重写 | 会毁掉这个项目唯一的优势：**你能讲清每一行** |

# 阶段 5：简历 + 面试（3 小时）

## 简历怎么写这个项目

**不要写**：「基于火山方舟 API 实现了支持工具调用的 AI Agent」——这句话谁都能写。

**要写**（每条都带一个具体决策）：

```
自研 AI Agent（Python，2300 行，无框架依赖）

- 手写 Anthropic Messages 协议调用，实现 tool_use / tool_result 闭环，
  支持 6 个文件工具与多轮上下文累积
- 设计「显式计划 + 两道闸门」：规划阶段只下发只读工具，
  执行前需用户批准整份计划，写操作逐次确认；
  实测拒绝计划时工作区零变更
- 实现断点恢复：会话状态原子落盘（tmp + replace），
  支持跨进程恢复并继续执行未完成任务
- 用阶段化工具清单实现权限隔离，模型侧无法越权调用写工具
```

## 面试必问 10 题（基于你的项目，全部能答）

1. agent 和普通 LLM 应用的区别是什么？
2. `tool_use` / `tool_result` 闭环怎么工作？为什么 `tool_result` 是 user 角色？
3. 对话历史怎么管理？长对话怎么办？
4. 怎么防止 agent 误删文件？
5. 怎么控制成本？预算怎么设计？
6. agent 中途中断了怎么恢复？
7. 怎么保证模型不改你批准的计划？
8. 改提示词后怎么知道变好了还是变坏了？（→ 阶段 4.2）
9. 你的 agent 能并发吗？瓶颈在哪？
10. 如果要把这个做成服务，要改什么？（→ 阶段 4.1）

**第 8 和第 10 题，现在的项目答不了**——这就是阶段 4 存在的理由。

1. **阶段 1 可能过得很快**——如果你读得比预期透，可以跳过练习 1，直接做练习 2。
