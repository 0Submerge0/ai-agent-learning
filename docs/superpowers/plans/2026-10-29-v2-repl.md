# V2 多轮对话 + 记忆 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 V1 的单次提问改成**同一个进程里能连续聊**：agent 记得你说过什么，提供 `/clear`（手动失忆）与 `/exit`。

**Architecture:** 新文件 `src/v2_repl.py`，从 `v1_tool.py` 复制改造。核心变化是把 `run_agent` 拆成 `run_turn(messages)`（处理一次用户提问的内部工具循环，返回更新后的历史）和 `run_repl()`（`input()` 死循环，管理历史与 `/` 命令）。**本版仍单文件，不抽 `agent\` 包**——沙箱与多工具（V3）才是抽包的触发点，提前抽违背「抽象被需求逼出来」的反目标。

**Tech Stack:** Python 3.14（uv）、`requests`、标准库。

**Spec:** `docs/superpowers/specs/2026-10-29-ark-agent-design.md`

## Global Constraints

- 接口、模型 ID、`TOOLS`、`list_dir`、`run_tool` 沿用 V1，`MODEL = "deepseek-v4-1-flash-260910"`
- 依赖上限：只有 `requests`
- 单文件 ~160 行（不含空行注释）
- 记忆 = `messages` 列表在 REPL 全程存活，每轮全量重发；**不写磁盘、不用数据库**
- 工具循环上限仍是 `MAX_ITERATIONS = 5`
- 网络失败**不再直接退出程序**：改为自定义 `ModelError`，REPL 捕获后继续聊天（这是「错误重试」概念的第一版：自动重试 2 次，仍失败则提示）
- key 打码、JSON 保护、`thinking` 原样回填等 V1 的既有防护全部保留

## Review Focus

1. **`/clear` 之后模型真的失忆**——清空 `messages` 后问「我叫什么」，必须答不上来（与清空前对比）。
2. **工具结果也必须留在历史里**——同一轮里模型先调工具、再回答，下一轮它还能引用上一轮看到的目录内容；如果把每轮结果丢进局部变量就破坏了这个。
3. **网络失败时进程不能死**——断网时 REPL 应打印错误并回到 `你>` 提示符，而不是 traceback 或 `sys.exit`。
4. **`input()` 读不到内容（Ctrl+D / Ctrl+C）**——不能裸崩，应优雅退出。
5. **上下文无限膨胀**——历史越攒越长，每轮打印累计输入 token 数并给出粗略预警，让「上下文成本」可见。

### Task 1: 把发请求改成「失败不退出」

**Files:**
- Create: `src/v2_repl.py`（先复制 V1 的常量、TOOLS、list_dir、run_tool、extract_text）

**Interfaces:**
- Consumes: 无
- Produces: `class ModelError(Exception)`；`call_model(messages: list, tools: list, retries: int = 2) -> dict`（失败抛 `ModelError`，不再 `sys.exit`）

- [ ] **Step 1: 复制 V1 作为起点**

```powershell
Copy-Item src\v1_tool.py src\v2_repl.py
```

- [ ] **Step 2: 改造 `call_model`**

签名变为 `call_model(messages, tools, retries=2)`。`sys.exit` 全部改为 `raise ModelError(...)`。`Timeout/ConnectionError` 自动重试（最多 `retries` 次，每次间隔打印「(网络抖动，重试中)」），仍失败再抛。非 2xx 抛 `ModelError(f"请求失败 HTTP {code}: {resp.text[:300]}")`（**截断响应体，避免把服务端大段错误文本塞进终端**）。

- [ ] **Step 3: 本地验证（不调模型）**

Run: `uv run python -c "import sys; sys.path.insert(0,'src'); import v2_repl as t; t.call_model([], [], retries=0)"`

Expected: 抛 `ModelError`（HTTP 400 之类），**不是** `SystemExit`，终端没有堆栈以外的副作用。

### Task 2: REPL 与记忆

**Files:**
- Modify: `src/v2_repl.py`

**Interfaces:**
- Consumes: Task 1 的 `ModelError` / `call_model`
- Produces: `run_turn(messages: list) -> list`（处理一轮提问，返回更新后的历史）；`run_repl() -> None`

- [ ] **Step 1: 写 `run_turn(messages)`**

从 V1 `run_agent` 改造：参数是历史，内部仍 `for range(MAX_ITERATIONS)` 做工具循环；每轮把模型回复 `append` 进 `messages`（含 thinking），`tool_use` 时把结果作为一条 user 消息 `append` 后 `continue`；结束时打印 `助手> <文本>`、累计用量，并打印一条上下文预警（`messages` 超过 20 条时提示「历史较长，上下文费用在涨，可用 /clear」）。**返回更新后的 `messages`**。

- [ ] **Step 2: 写 `run_repl()`**

`while True:` 内 `input("你> ")`，处理 `/exit`、`/clear`、空输入；普通问题：`messages.append(user消息)` → `messages = run_turn(messages)`。`KeyboardInterrupt`/`EOFError` 静默退出。启动时打印一句「输入 /clear 清空记忆，/exit 退出」。

- [ ] **Step 3: 记忆演示（本版教学重点）**

Run: `uv run python src/v2_repl.py`，然后：

```
你> 记住我叫阿杰
助手> （应回答记住了）
你> 我叫什么名字
助手> （应回答：阿杰）
你> /clear
（记忆已清空）
你> 我叫什么名字
助手> （应答不上来）
你> /exit
```

Expected: 三条全对——**这是 V0「它记不住」到 V2「它能记住」的闭环**。

- [ ] **Step 4: 工具记忆演示**

Run: 同上，输入「看看当前目录里有什么」，然后输入「刚才看到的目录里有没有 src」，看它能否引用上一轮的目录内容。

Expected: 能引用（因为工具结果留在了历史里）。

### Task 3: V2 讲义

**Files:**
- Create: `docs/notes/v2.md`

**Interfaces:**
- Consumes: Task 2 真实输出
- Produces: 讲义，结构同前两版

- [ ] **Step 1: 写讲义**

「三件事」：
1. **记忆 = 你的 `messages` 列表，不是模型的能力**——模型那边仍然没有记忆，是你在每次请求里全量重发历史，制造了「记忆」的假象。
2. **`/clear` 是手动失忆**——它做的事就是 `messages = []`。清空后模型立刻忘掉，反证了第 1 点。
3. **工具结果留在历史里，下一轮还能引用**——agent 的记忆不仅包括「对话」，还包括「它做过的事」。

对比表：V0（无历史）/ V1（单轮内的工具历史）/ V2（跨轮会话历史）。
