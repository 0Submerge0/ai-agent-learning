# V0 单轮对话 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出一个能跑的 Python 脚本：把一句话发给模型、把回复打出来，并让学员亲眼看到「模型没有记忆」。

**Architecture:** 单个脚本 `src/v0_chat.py`，用 `requests` 直接 POST 到火山方舟 Coding Plan 的 Anthropic Messages 接口。不引入 SDK、不抽象、不建包结构——`agent\` 包要到 V2 才出现。

**Tech Stack:** Python 3.14（uv 管理）、`requests`、标准库 `os`/`sys`/`json`。

**Spec:** `docs/superpowers/specs/2026-10-29-ark-agent-design.md`

## Global Constraints

- 模型接口：`POST https://ark.cn-beijing.volces.com/api/coding/v1/messages`
- 请求头：`x-api-key: <ARK_API_KEY>`、`anthropic-version: 2023-06-01`、`content-type: application/json`
- 模型 ID：`doubao-seed-2-1-pro`
- API key 只从 `process.env` 等价物（`os.environ["ARK_API_KEY"]`）读取；**任何文件不得出现明文 key**
- 依赖上限：只允许 `requests`；禁止 `openai`、`anthropic`、`langchain*`
- 运行命令统一为 `uv run python src/xxx.py`；不得要求改系统 PATH
- 代码行数目标 ~40 行（不含注释）；注释只回答「为什么」，长篇讲解放 `docs/notes/`
- 文件操作类工具本版不涉及；`workspace\` 沙箱到 V3 才出现

## Review Focus

按最可能咬人的顺序。每一项都要在本版有对应处理，不能留给「以后」：

1. **`ARK_API_KEY` 未设置** → 应输出一句中文提示（如「未找到 ARK_API_KEY 环境变量」）并退出码 1，而不是抛 `KeyError` 堆栈。
2. **Windows 控制台编码** → 本机 PowerShell 输出中文曾出现乱码；脚本必须显式把 stdout 设为 UTF-8，否则中文回复可能 `UnicodeEncodeError`。
3. **接口非 2xx** → 应打印 HTTP 状态码和响应体原文（里面含 `error.code`，如 `InvalidEndpointOrModel.NotFound`），而不是 `raise_for_status()` 的裸异常。
4. **响应里没有任何 `text` 块**（只有 `thinking`，或 `max_tokens` 太小被截断）→ 不能静默输出空字符串；应打印 `stop_reason` 说明原因。
5. **命令行参数带空格**（如 `"帮我写个标题"`）→ 必须整句作为一个参数传入，不能按空格切分。

### Task 2: V0 单轮对话脚本

**Files:**
- Create: `src/v0_chat.py`

**Interfaces:**
- Consumes: Task 1 的环境与 `requests`
- Produces:
  - `build_payload(user_text: str) -> dict` — 组装请求体
  - `extract_text(data: dict) -> str` — 从响应 `content` 数组中取出所有 `type=="text"` 块的文字并拼接
  - `chat(user_text: str) -> None` — 发请求并打印结果与用量
  - 模块常量：`API_URL`、`MODEL = "doubao-seed-2-1-pro"`、`SYSTEM_PROMPT`、`MAX_TOKENS = 512`

- [ ] **Step 1: 写 `src/v0_chat.py`**

必须满足 Review Focus 全部 5 条。关键实现点：

- `sys.stdout.reconfigure(encoding="utf-8")` 放在文件顶部附近，解决第 2 条
- key 读取用 `os.environ.get("ARK_API_KEY")`，为空则打印中文提示 + `sys.exit(1)`，解决第 1 条
- 请求用 `requests.post(..., timeout=60)`，**不用** `raise_for_status()`，改为判断 `resp.status_code != 200` 时打印状态码 + `resp.text`，解决第 3 条
- 取文本走 `extract_text()`，若结果为空则打印 `stop_reason` 与 `usage`，解决第 4 条
- 用户输入取 `sys.argv[1]`（整串），缺省时给一句默认问题，解决第 5 条
- `SYSTEM_PROMPT` 用一句中文，例如「你是一个简洁的中文助手。」

实现顺序建议：常量 → `build_payload` → `extract_text` → `chat` → `__main__`。

- [ ] **Step 2: 正常路径验证**

Run: `uv run python src/v0_chat.py "用一句话介绍你自己"`

Expected: 打印一段中文回复，并打印 `usage`（含 input/output tokens）

- [ ] **Step 3: 失败演示（V0 的教学重点）**

先告诉它一个名字，再单独问一次：

```bash
uv run python src/v0_chat.py "记住我叫阿杰"
uv run python src/v0_chat.py "我叫什么名字"
```

Expected: 第二次它**答不出**（或答错）。这就是「模型没有记忆」——每次请求都是全新的、无状态的。这一条要写进 `docs/notes/v0.md`。

- [ ] **Step 4: 参数带空格验证**

Run: `uv run python src/v0_chat.py "帮我给一个卖手冲咖啡的小店起 3 个名字"`

Expected: 整句被当作一个问题（模型不会只看到「帮我给一个卖手冲咖啡的小店起」）

- [ ] **Step 5: 缺 key 验证**

Run: `$env:ARK_API_KEY=""; uv run python src/v0_chat.py "hi"`

Expected: 输出中文提示「未找到 ARK_API_KEY 环境变量」，退出码 1，无 Python 堆栈

- [ ] **Step 6: 提交**

```bash
git add src/v0_chat.py
git commit -m "feat(v0): 单轮对话脚本"
```

5. **复述题 + 自检** —— 3 个复述题（如「`messages` 为什么是数组而不是一个字符串？」），附自检清单：答不出时回去看讲义第几节
