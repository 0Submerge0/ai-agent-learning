# V5 显式计划 + 计划审批 + 断点恢复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 V4 里「靠提示词说计划」升级成**代码里真实存在的计划对象**：先规划、用户批准、再执行、逐项更新状态；会话可落盘，退出后能 `/resume` 接着做。

**Architecture:** V4 的 `tools.py` / `tools_v4.py` / `agent` 其它模块保持可用；新增三层：
- `agent/plan.py`：`Task` / `Plan`，状态机 + 渲染 + JSON 序列化。
- `agent/session_store.py`：把 `goal / phase / plan / messages / budget` 原子写入 `sessions/`。
- `agent/tools_v5.py`：阶段化工具集——规划阶段只给「只读工具 + `create_plan`」，执行阶段给「V4 全部工具 + `update_task`」。
新入口 `src/v5_planner.py` 负责两阶段流程与 `/plan`、`/resume`。

**Tech Stack:** Python 3.14（uv）、`requests`、标准库 `dataclasses`/`json`/`pathlib`/`datetime`。

**Spec:** `docs/superpowers/specs/2026-10-29-ark-agent-design.md`（V4 的 5.8 明确把显式 plan 留给 V5）

## Global Constraints

- 沙箱、写操作 `y/N` 确认、预算、日志**全部保留**
- 规划阶段**不提供任何写工具**；执行阶段**不提供 `create_plan`**
- 计划最多 12 个任务，状态只允许 `pending / in_progress / done / failed / skipped`
- 计划审批是**第二道闸门**：批准计划 ≠ 批准每个写操作
- `sessions/` 加入 `.gitignore`；会话文件含对话内容，默认不提交
- 依赖仍只有 `requests`
- V3 / V4 入口一行不改，仍能原样跑

## Review Focus

1. **阶段隔离真的生效**：规划阶段调 `write_file` 必须被拒；执行阶段调 `create_plan` 也必须被拒。
2. **计划拒绝后不动手**：用户对计划答 `n`，磁盘不能有任何变化。
3. **状态可追踪**：`update_task` 后 `/plan` 能立刻看到新状态；全部完成时给出明确结论。
4. **断点恢复**：`/resume` 能恢复计划、对话、预算；恢复后输入「继续」接着执行。
5. **存档不写坏**：先写 `.tmp` 再原子替换；中断不会留下半个 JSON。

### Task 1: 计划对象

**Files:**
- Create: `src/agent/plan.py`

**Interfaces:**
- Produces: `STATUSES`；`Task`；`Plan(goal)`；`Plan.set_tasks(titles)`；`Plan.update(task_id, status, note="")`；`Plan.render()`；`Plan.to_dict()` / `Plan.from_dict(data)`；`Plan.is_complete`

- [ ] **Step 1: 写 `Task` / `Plan`**

`set_tasks` 清洗空白、限制 1–12 条、自动编号 1..N。`update` 校验状态枚举、任务 id 存在，`note` 截断到 200 字符。

- [ ] **Step 2: 写渲染与序列化**

`render()` 输出：
```
目标：...
任务：
  1. [pending] ...
  2. [done] ...
进度：1/2 完成
```
`to_dict` / `from_dict` 保留 `created_at`、`updated_at`。

- [ ] **Step 3: 本地验证**

Run: 创建计划、更新状态、渲染、`to_dict` → `from_dict` 再渲染，两次输出一致；非法状态、空任务、超过 12 条都要抛 `ValueError`。

### Task 3: 阶段化工具集

**Files:**
- Create: `src/agent/tools_v5.py`

**Interfaces:**
- Consumes: `agent.tools_v4` 的 `TOOLS_V4` / `run_tool` / `summarize_args`；`agent.plan.Plan`
- Produces: `PLANNING_TOOLS`；`EXECUTION_TOOLS`；`run_planning_tool(name, args, plan, log=None) -> tuple[str, bool]`；`run_execution_tool(name, args, plan, ask=None, log=None) -> str`

- [ ] **Step 1: 定义两套工具 schema**

规划：`list_dir` / `read_file` / `search_files` + `create_plan(tasks)`。
执行：V4 的 6 个工具 + `update_task(task_id, status, note)`。

- [ ] **Step 2: 写分发与阶段校验**

规划阶段遇到写工具直接返回「规划阶段不能调用」。执行阶段遇到 `create_plan` 同样拒绝。`update_task` 不需要 `y/N`（它只改内存状态），但要写日志。

- [ ] **Step 3: 本地验证（不调模型）**

测：规划阶段调 `write_file` 被拒；执行阶段调 `create_plan` 被拒；`create_plan` 建 3 个任务；`update_task` 改成 done；非法状态返回可读错误。

### Task 4: V5 入口

**Files:**
- Create: `src/v5_planner.py`

- [ ] **Step 1: 写规划阶段 `planning_phase(goal, budget, log)`**

工具只给 `PLANNING_TOOLS`。循环最多 6 次；模型没提交计划就提醒一次；`create_plan` 成功后立即停止并把计划交给用户审批。预算检查与 V4 相同。

- [ ] **Step 2: 写审批闸门**

打印计划，问 `批准这个计划? (y/N)`。答 `y` 才进入执行；否则记录 `plan_rejected`，磁盘无变化。

- [ ] **Step 3: 写执行阶段 `execution_phase(goal, plan, messages, budget, store, log)`**

工具给 `EXECUTION_TOOLS`，system prompt 里带当前计划。每轮工具结果后保存会话；结束时打印计划进度，未完成任务要明确提示。

- [ ] **Step 4: 写 REPL 与 `/plan`、`/resume`、`/clear`**

`/resume` 读最近会话，恢复 `messages / plan / phase / budget`；若阶段是 `executing`，提示输入「继续」；输入「继续」时直接进执行循环，不重新规划。`/clear` 清空记忆、计划、预算。

- [ ] **Step 5: 本地验证（不调模型）**

用合成会话测 `/resume` 的恢复与 `/plan` 输出；确认没有会话文件时给出友好提示。

- [ ] **Step 6: 模型驱动演示**

任务：整理 workspace。预期：先勘察 → `create_plan` → 打印计划等 `y` → 执行 → 每步 `update_task` → 最后 `2/2 完成`。再跑一次「计划答 n」，确认磁盘无变化。

### Task 5: V5 讲义 + README

**Files:**
- Create: `docs/notes/v5.md`
- Modify: `README.md`

- [ ] **Step 1: 写讲义**

三件事：
1. **计划变成一等公民**：V4 的计划是模型说的一段话，V5 的计划是代码里的对象，能被检查、渲染、保存。

3. **断点恢复靠「状态」不靠「记忆」**：保存的是 messages + plan + phase + budget，恢复的是现场，不是模型记忆。
