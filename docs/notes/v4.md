# V4：多工具、任务规划、日志与成本控制

## 1. 这一版做了什么

V3 是「4 个工具的文件助手」，V4 把它收口成一个**能自己安排顺序、每一步都留痕、花钱有上限**的助手：

1. **工具从 4 个变成 6 个**：新增 `search_files`（按模式搜文件）和 `write_file`（写文本文件）。
2. **会先勘察、再说计划、再执行、最后复查**：不是新代码结构，是 `SYSTEM_PROMPT` 教出来的行为。
3. **全部事件写日志**：`logs/session-YYYYMMDD-HHMMSS.log`，一行一个 JSON，事后能还原。
4. **会话预算**：默认 20000 tokens，超限就停，不再调模型、不再执行工具。

真实运行（一个混合文件整理任务）：

### 2.2 新工具 ①：`search_files`（只读，41–81 行）

```python
# tools_v4.py 第 52–70 行
def search_files(pattern: str, path: str = ".") -> str:
    pattern = (pattern or "").strip()
    if not pattern:
        raise ValueError("搜索模式不能为空")
    # 模式只允许是「文件名模式」，不能借它跳出 workspace。
    if Path(pattern).is_absolute() or ".." in Path(pattern).parts:
        raise ValueError(f"搜索模式不能是绝对路径或包含 ..：{pattern}")

    base = safe_path(path, must_exist=True)
    ...
    for entry in base.rglob(pattern):
        target = entry.resolve()
        # 符号链接可能指向 workspace 外面，逐个再验一次。
        if not target.is_relative_to(root):
            continue
```

有两个容易漏的点：

1. **参数本身也能越界**。不只 `path` 要检查，`pattern` 也可能是 `../*.py` 或 `C:/Windows/*.dll`。所以第 57–58 行先拒掉绝对路径和 `..`。
2. **结果还要再验一次**。`rglob` 可能穿过符号链接，第 69–70 行对每个结果 `resolve()` 后重新检查是否还在 workspace 内。

实测：

```
../*.py -> 工具执行失败：搜索模式不能是绝对路径或包含 ..：../*.py
C:/Windows/*.dll -> 工具执行失败：搜索模式不能是绝对路径或包含 ..：C:/Windows/*.dll
```

**Java 类比**：这像「入参校验」和「返回值校验」都要做——不能只信入口，也不能只信出口。

### 2.3 新工具 ②：`write_file`（写操作，84–93 行）

```python
# tools_v4.py 第 84–93 行
def write_file(path: str, content: str, overwrite: bool = False) -> str:
    p = safe_path(path)
    if p.exists():
        if p.is_dir():
            raise ValueError(f"目标是一个目录，不能当文件写：{path}")
        if not overwrite:
            raise ValueError(f"目标已存在，拒绝覆盖（需要 overwrite=true）：{path}")
    p.parent.mkdir(parents=True, exist_ok=True)
    p.write_text(content, encoding="utf-8")
    return f"已写入 {rel(p)}（{len(content)} 字符）"
```

默认**不覆盖**。要覆盖必须显式传 `overwrite=true`——这比「默默覆盖」安全得多，因为覆盖是不可逆的。

确认前的计划里会显示**内容预览**（96–110 行）：

```python
return f"写入 workspace/{args.get('path')}（{len(content)} 字符{extra}）\n         预览：{preview}"
```

实测：

```
[计划] 写入 workspace/report.md（1004 字符）
         预览：# Workspace 整理报告\n\n整理时间：本次会话\n整理范围：work…
```

**为什么要预览？** 因为「写文件」比「搬文件」更容易夹带东西。只看一句「写入 report.md」就按 `y`，等于盲签。

### 2.4 确认闸门：还是 V3 那一套，多了一个 `log`

`WRITE_TOOLS` 在 V4 是「V3 的两个 + `write_file`」（38 行）：

```python
WRITE_TOOLS = WRITE_TOOLS_V3 | {"write_file"}
```

`run_tool` 的确认逻辑没变，只是加了两处日志（128–148 行）：

```python
if name in WRITE_TOOLS:
    if name == "write_file":
        target = safe_path(args.get("path", ""))
        if target.exists() and not args.get("overwrite"):
            return f"工具执行失败：目标已存在，拒绝覆盖..."

    plan = describe_write_v4(name, args)
```

**顺序值得记**：先检查「目标存在但没开 overwrite」，再打印计划、再问。这样用户不会先按一次 `y` 才被告知「其实不能覆盖」。

### 2.5 日志：`logger.py`（35 行）

整个模块就一个类：

```python
# logger.py 第 10–25 行
class SessionLogger:
    def __init__(self, log_dir: Path = LOG_DIR):
        log_dir.mkdir(parents=True, exist_ok=True)
        stamp = datetime.now().strftime("%Y%m%d-%H%M%S")
        self.path = log_dir / f"session-{stamp}.log"
        self._fh = self.path.open("a", encoding="utf-8")

    def log(self, event: str, **fields) -> None:
        record = {"ts": datetime.now().isoformat(timespec="milliseconds"), "event": event}
        record.update(fields)
        self._fh.write(json.dumps(record, ensure_ascii=False, default=str) + "\n")
        # 每条都 flush：即使下一步程序崩了，已经发生的事也留在磁盘上。
        self._fh.flush()
```

为什么用 **JSONL**（一行一个 JSON），而不是普通文本或一个大 JSON 数组？

- 一行一条，**追加写**，不用读完整个文件再改；
- 崩了也只丢最后半行，前面的都在；
- 想统计什么，`grep` 或几行 Python 就能算。

实测日志片段：

```
{"ts": "2026-11-10T11:52:51.100", "event": "write_plan", "tool": "mkdir", "args": {"path": "images"}}
{"ts": "2026-11-10T11:53:00.319", "event": "write_plan", "tool": "write_file", "args": {"path": "report.md", "chars": 1004, "overwrite": false}}
```

一次整理任务的事件统计：

```
19 tool_call
19 tool_result
10 write_confirm
10 write_plan
 8 model_request
 8 model_response
 5 plan_text
 1 session_start
 1 user_message
 1 session_end
```

**两个刻意的取舍**：

1. `user_message` 只记 `chars`，不记原文——万一你往对话里粘了 key，也不会落盘。
2. `write_file` 的参数用 `summarize_args` 摘要（41–49 行），只记 `path / chars / overwrite`，不记全文：

```
原始参数 JSON 长度 = 456
摘要 JSON = {"path": "report.md", "chars": 400, "overwrite": false}
摘要 JSON 长度 = 55
```

**日志的第一原则不是「记得多」，是「记得能查，且不给自己埋雷」。**

### 2.6 预算：`budget.py`（52 行）

```python
# budget.py 第 31–44 行
def add(self, usage: dict) -> str:
    self.input_tokens += int((usage or {}).get("input_tokens") or 0)
    self.output_tokens += int((usage or {}).get("output_tokens") or 0)

    if self.used >= self.max_tokens:

    if not self._warned and self.used >= self.max_tokens * WARN_RATIO:

```

三个状态：`ok` / `warning`（80%）/ `exhausted`（100%）。`warning` 只报一次，否则每轮都刷屏。

上限从哪来？

```python
# budget.py 第 10–17 行
raw = (os.environ.get("MAX_SESSION_TOKENS") or "").strip()
try:
    max_tokens = int(raw) if raw else DEFAULT_MAX_TOKENS
except ValueError:

```

默认 20000；环境变量写错（比如 `abc`）不会让程序起不来，退回默认值。

### 2.7 入口：`v4_assistant.py`（176 行）

**规划在哪？** 在提示词里（19–28 行），不在数据结构里：

```python
SYSTEM_PROMPT = (
    "你是一个文件整理助手，只能操作 workspace 目录里的文件。"
    "处理任务时严格按四步走："
    "1) 先勘察：用 list_dir / search_files / read_file 了解现状，不要凭猜测回答；"
    "2) 再说计划：把准备做的步骤按顺序列出来；"
    "3) 再执行：需要写操作时调用工具，用户会在每一步确认；"
    "   互相独立的操作（比如移动多个文件）可以在一次回复里同时发起多个工具调用，不要一个一个来；"
    "4) 最后复查：用 list_dir / read_file 验证结果，再汇报做了什么。"
    "如果工具返回路径越界、目标已存在之类的错误，如实说明并调整，不要反复尝试同一个无效调用。"
)
```

这就是设计文档 5.8 的决定：**V4 的「规划」先用提示词驱动，不引入显式 plan 结构**（那属于 V5）。你现在看到的「它自己列了 6 步」，本质是模型按提示词生成的一段文本，代码里没有任何 `Plan` 类。

**预算检查放在哪？** 两个地方：

1. **每轮循环开头**（41–43 行）——超了就不再发请求：

```python
if budget.used >= budget.max_tokens:
    print("（会话预算已用完，不再调用模型。输入 /clear 可以重置预算）")
    return messages
```

2. **每次模型返回后、执行工具前**（63–86 行）——这一次调用把预算撑爆了，就停止，**不执行它刚请求的工具**：

```python
status = budget.add(usage)
...
elif status == "exhausted":
    pending = [b for b in data["content"] if b.get("type") == "tool_use"]
    if pending:
        messages.append({"role": "user", "content": [ ... "会话预算已用完，工具未执行。" ... ]})
    print("（预算用完：... 输入 /clear 重置）")
    return messages
```

`pending` 那段是在补 `tool_result`：模型已经发出 `tool_use`，历史里必须跟一条对应的 `tool_result`，否则下次请求格式不合法。**即使要停，也要把话说完整。**

**计划文本也打印出来**（88–93 行）：

```python
if stop == "tool_use":
    plan_text = extract_text(data)
    if plan_text.strip():
        print("助手> " + plan_text)
```

V3 只打印 `[工具]`，模型在 `tool_use` 轮里说的计划会被吞掉。V4 要讲「规划」，就得让人看见它。这是实测后才补的——第一次演示时，计划全都看不见。

**`MAX_ITERATIONS = 16`**（29 行）。这个数字是跑出来的，不是拍脑袋：第一版设 10，真实整理任务在第 10 轮刚好卡住（6 个文件一个一次 `move_file`），报告写完但没来得及汇报。后来加了两条改进：提示词允许批量调用 + 上限提到 16。日志里数得清清楚楚：

```
move_file ... model_request ... move_file ... model_request ... move_file
```

**`/clear` 同时重置两样东西**（149–154 行）：

```python
if line == "/clear":
    messages = []
    budget.reset()
    logger.log("clear")
    print("（记忆已清空，预算已重置）")
```

只清记忆不清预算，会出现「记忆是空的，但额度已经花完」的怪状态。

## 3. 值得记住的三件事

### ① 规划不是数据结构，是提示词行为

很多人以为「任务规划」要写个 `Plan` 类、拆成 `Task` 列表、加状态机。V4 没有。它只是一段系统提示词 + 同一套工具循环。

- 提示词要求「先勘察 → 再说计划 → 再执行 → 最后复查」；
- 模型就在一次回复里先输出计划文字，再发 `tool_use`；
- 你的代码只是把计划文字打印出来，把工具调用执行掉。

**好处**：几乎没有代码成本，行为立刻能看见。
**代价**：它不稳定——模型可能跳过勘察、可能不复查、可能把计划说得含糊。要稳定就得升级到显式 plan（V5 的事）。

> Java 类比：这不是「写了一个工作流引擎」，而是「给执行器写了一段操作手册」。引擎还是那个 `while` 循环。

### ② 日志是「事后能解释」的前提

模型的行为不能复现：同样一句话，今天调 3 个工具，明天可能调 5 个。出了事，你没法「再跑一次看看」。

日志把「它做了什么」变成事实：

- 调了几次模型、每次多少 token、耗时多少；
- 选了哪些工具、参数是什么；
- 哪次写操作被拒绝；
- 预算什么时候用完。

而且日志要**能读、能算、不泄密**：JSONL 一行一条，`grep`/`jq` 都能处理；`user_message` 只记长度；`write_file` 只记摘要。

### ③ 成本控制要设在「花钱之前」

预算检查有两个位置，缺一不可：

- **循环开头**：已经超了，就别再发请求；
- **模型返回后、工具执行前**：这次调用把额度撑爆了，就别再执行它请求的工具。

如果只在最后打印「你花了多少钱」，那不是控制，是**事后通知**。控制必须发生在动作之前。

实测（`MAX_SESSION_TOKENS=800`）：

```
[工具] read_file({"path": "旧笔记.txt"})
       这是一些旧笔记。
（预算用完：845/800 tokens（剩 0）。本轮停止，未执行的工具不会执行；输入 /clear 重置）
```

注意：最后那次模型返回里可能还有工具请求，但一个都没执行。

## 4. 改一改试试（都实测过）

**1. 把 `MAX_ITERATIONS` 改成 1，多步任务立刻只剩勘察。**

```python
v4_assistant.MAX_ITERATIONS = 1
```

实测：

```
你> 帮我整理 workspace：图片放进 images/，文本放进 texts/，其他放进 other/。
助手> 我先查看 workspace 的当前情况。
[工具] list_dir({"path": "."})
       .gitkeep  0 B
       发票1.jpg  10 B
       ...
（这一轮转满了 1 次工具循环，先停了）
```

workspace 一个文件都没动。**循环次数就是「这一轮最多能问模型几次」**；给 1 次，它就只够勘察。

**2. 把预算设成 0，模型一次都不会调。**

```powershell
$env:MAX_SESSION_TOKENS="0"
```

实测：

```
预算：0 tokens（可用环境变量 MAX_SESSION_TOKENS 覆盖）。
你> 帮我整理 workspace
（会话预算已用完，不再调用模型。输入 /clear 可以重置预算）
```

一行都没发出去。这说明预算检查确实在**调用之前**，不是事后统计。

**3. 把日志摘要换成原始参数，日志体积立刻膨胀。**

`summarize_args` 对 `write_file` 只记 `chars`。如果直接 `log(..., args=args)`：

```
原始参数 JSON 长度 = 456
摘要 JSON = {"path": "report.md", "chars": 400, "overwrite": false}
摘要 JSON 长度 = 55
```

内容越长，差距越大。而且原文里可能有你不想落盘的东西。改完记得改回去。

**Q2. 预算检查为什么要有两处？只留「循环开头」那一处行不行？**

<details>
<summary>答不出时看</summary>

**Q3. 日志为什么用 JSONL？为什么不直接记模型的完整请求和 `write_file` 全文？**
