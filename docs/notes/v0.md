# V0：一次对话，看清 HTTP 往返

## 1. 这一版做了什么

一句话发给模型，模型回一句。**没有记忆，没有工具，没有循环**。

### 前置：先设置 key

脚本从环境变量读 `ARK_API_KEY`。在 PowerShell 里执行一次（把 `你的key` 换成真的 key）：

```powershell
$env:ARK_API_KEY = "你的key"
```

注意：**只对当前这个终端窗口生效**，关掉窗口就没了，新开窗口要重设。想让它在当前窗口里永久生效，写进系统环境变量；但那样你得重启终端才会被读到。

> 本版脚本**不读 `.env` 文件**。`.env.example` 只是给以后的版本留的占位，你现在复制成 `.env` 填进去也没用。

### 跑起来

```powershell
uv run python src/v0_chat.py "用一句话介绍你自己"
```

真实输出：

```
我是字节跳动开发的人工智能，可为你提供信息查询、问题解答、创意生成等各类实用帮助。

[用量] 输入 54 / 输出 154 tokens
```

代码一共 90 行，去掉空行和注释约 67 行。

> 如果终端显示的仍然是乱码（比如 `杈撳嚭` 这种），那是**终端**在用 GBK 解码 UTF-8 字节，不是 Python 的问题。先执行 `[Console]::OutputEncoding = [Text.Encoding]::UTF8` 就正常了。

## 2. 代码逐块讲

### 顶部的编码设置（第 8–11 行）

```python
if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
    sys.stderr.reconfigure(encoding="utf-8", errors="replace")
```

**去掉会怎样**：模型回你的中文在 Windows 上可能抛 `UnicodeEncodeError`，或者显示成 `????`。

**为什么需要**：Java 里 `System.out` 的编码由 JVM 启动参数处理；Python 默认跟随系统 locale，Windows 中文环境就是 GBK。这行是告诉 Python「不管系统怎么设置，我都按 UTF-8 输出」。

`hasattr` 那层判断是为了防止某些 IDE 或输出重定向把 `sys.stdout` 换成没有 `reconfigure` 方法的对象。

### 常量区（第 13–17 行）

```python
API_URL = "https://ark.cn-beijing.volces.com/api/coding/v1/messages"
MODEL = "doubao-seed-2-1-pro"
SYSTEM_PROMPT = "你是一个简洁的中文助手，回答控制在三句话以内。"
MAX_TOKENS = 512
DEFAULT_QUESTION = "用一句话介绍你自己"
```

**`SYSTEM_PROMPT` 是什么**：模型收到的「角色设定」，它在对话之外先于你的问题生效。Java 类比：像 Servlet 的 `init` 参数——不是你每次请求传的，而是框架在每次处理前先塞进去的。它影响语气和长度，但**不影响模型有没有记忆**（这是 V0 最容易被误解的一点）。

**`DEFAULT_QUESTION`**：不带参数运行时用的默认问题，由第 90 行读取。

**为什么不把 URL 直接写在 `requests.post` 那里**：V1 会把整个文件复制一份改成 `v1_tool.py`。写死在调用处的话，那时候就是两份文件里各有一份 URL，改地址要记得改两处——而人是会忘的。

### `build_payload`（第 20–27 行）

```python
return {
    "model": MODEL,
    "max_tokens": MAX_TOKENS,
    "system": SYSTEM_PROMPT,
    "messages": [{"role": "user", "content": user_text}],
}
```

**去掉会怎样**：没有请求体，`requests.post` 只能发空请求。

**`messages` 为什么是数组**：因为真实对话有多个角色轮流说话。哪怕现在只有一句，格式也必须是数组——这个形状在 V2 会直接决定你怎么实现多轮。

Java 类比：`List<Message>`，其中 `Message` 就是 `{role, content}` 两个字段的 POJO。

### `extract_text`（第 30–33 行）

```python
blocks = data.get("content", [])
return "".join(b.get("text", "") for b in blocks if b.get("type") == "text")
```

**去掉会怎样**：你只能打印整个 JSON，看不到干净的回复。

**为什么不能直接取 `data["content"]`**：响应里的 `content` **不是一个字符串，而是一个「块」的数组**。

实测这一版请求拿到的块类型是：

```
['thinking', 'text']
```

也就是说，模型每次回复里**已经带了思考块**，只是被这行过滤掉了。V1 加工具后还会多出 `tool_use` 块——不加过滤就会把工具参数当成回复打印出来。

### `chat`（第 36–85 行）

按顺序做六件事：

1. **清洗并读取 key**（第 37–41 行）：`(os.environ.get("ARK_API_KEY") or "").strip()`。
   **为什么要 `.strip()`**：从文件读出来的 key 常带尾随换行。带着换行发请求，服务器会报一个看起来像网络错误的失败，你会照着"网络问题"排查半天。实测过：`"ark-xxx\n"` 会得到 `Invalid leading whitespace... in header value`。
   **为什么不用 `os.environ[...]`**：那样 key 缺失时会抛 `KeyError` 和一堆堆栈，你看不出「是没设环境变量」还是「代码有 bug」。
2. **发请求**（第 43–54 行）：注意请求头是 `x-api-key`，**不是** `Authorization: Bearer`。
   **去掉会怎样**：401。
3. **区分两类失败**（第 55–63 行）：超时和连不上，说"可能是网络"；其他请求异常说"请求没有发出去，检查 key 里有没有空格"。并且把异常信息里的 key **打码**——requests 的 `InvalidHeader` 异常会把 header 原值（也就是你的 key）拼进消息里，不打码就会印在终端上。
4. **判断状态码**（第 65–69 行）：非 200 时把 `resp.text` 原样打出来。
   **为什么不用 `raise_for_status()`**：服务端返回的 `error.code`（比如 `InvalidEndpointOrModel.NotFound`、`AuthenticationError`）才是真正的诊断信息，`raise_for_status()` 会把它埋在异常里。
5. **解析 JSON**（第 71–77 行）：`resp.json()` 也可能失败——代理、公司网关、机场 WiFi 认证页都会返回 `200` + 一段 HTML。捕获 `ValueError` 后打印前 200 个字符，比甩 20 行堆栈有用。
6. **打印结果与用量**（第 78–85 行）：`usage` 里的 `input_tokens` / `output_tokens`。
   **为什么关心它**：这就是你付钱的地方，也是后面判断「上下文是不是快爆了」的唯一依据。

**第 2、3、5 条是原计划没有的**，实测时分别踩到了「60 秒超时甩 traceback」和「key 带换行被误诊成网络问题」，所以补进来了。这属于 spec 里「出问题要能定位」那一条，不算跑偏。

### `__main__`（第 88–90 行）

```python
chat(" ".join(sys.argv[1:]) if len(sys.argv) > 1 else DEFAULT_QUESTION)
```

**为什么是 `" ".join(...)` 而不是 `sys.argv[1]`**：命令行里**不加引号**时，空格会把一句话切成好几段：

```
> uv run python src/v0_chat.py 帮我给咖啡店起 3 个名字
['帮我给咖啡店起', '3', '个名字']
```

只取 `argv[1]` 的话，你发出去的是「帮我给咖啡店起」，模型给你一个莫名其妙的回答，而**脚本不会告诉你它丢了字**。拼回去之后，加不加引号都能用。

**为什么用命令行参数而不是 `input()`**：命令行参数能让你把一句话整体传进去。`input()` 留到 V2 的交互式 REPL 再上。

## 3. 值得记住的三件事

### ① 模型没有记忆——这是 V0 唯一真正要理解的事

连续跑两次：

```powershell
uv run python src/v0_chat.py "记住我叫阿杰"
# 好的，我已经记住你叫阿杰啦，之后都会这么称呼你哦。

uv run python src/v0_chat.py "我叫什么名字"
# 我暂时还不知道你的名字哦，你可以告诉我你的称呼呀。
```

第一次它说「记住了」，第二次它不知道你叫什么。

**不是它撒谎**，而是「记住」只发生在**那一次请求内部**。每次运行都是一次全新的、无状态的调用——你的程序里没有把上一次的对话存到任何地方，模型那边也不会替你存。

Java 类比：像每次请求都 new 一个新的、没有任何字段的 Service 实例。**记忆必须由你的代码提供**，这就是 V2 要写的东西：把历史 `messages` 攒起来，每次完整发过去。

### ② 响应是「块」的数组，不是字符串

现在你看到的是：

```json
{"type": "text", "text": "..."}
```

实际还有：

```json
{"type": "thinking", "thinking": "...", "signature": "..."}
```

V1 还会多出：

```json
{"type": "tool_use", "id": "call_xxx", "name": "list_dir", "input": {"path": "."}}
```

所以过滤 `type` 这个习惯，从第一天就要养成。

### ③ 认证方式跟「主流」不一样

| | 火山方舟 Coding Plan | OpenAI |
|---|---|---|
| 地址 | `/api/coding/v1/messages` | `/v1/chat/completions` |
| 认证头 | `x-api-key` | `Authorization: Bearer` |
| 请求体 | `messages` + `system`（顶层） | `messages`（system 也是其中一条） |

**概念完全一样，只是字段名不同**。看懂这一版之后，换任何厂商只是改这几行。

## 4. 改一改试试（自愿，但强烈建议做前两个）

下面三条都实际跑过，输出是真实的，不是预测。

**1. 把 `MODEL` 换成 `"claude-sonnet-4-5"`，别的都不动。**

→ 照样能跑。因为服务端把这个别名路由到了另一个模型。想看真实路由结果，在 `chat()` 里加一行 `print(data["model"])`，实测输出：

```
doubao-seed-2-1-turbo-260628
```

这跟 V1 会遇到的「工具名写错」是同一类问题：**名字对不上时，要先确认是「真的不存在」还是「别名指到别处」**。

**2. 把 `MAX_TOKENS` 改成 `16`，再问一句长问题。**

→ 实测输出：

```
杭州是浙江省省会，坐落于钱塘江下游、京杭大运河南端，
```

注意脚本**照样正常打印，没有任何警告**——因为 `extract_text` 拿到了非空字符串。**「有内容」不等于「完整」**，这个区别只有 `stop_reason`（此时的值为 `max_tokens`）能告诉你。V2 会把 `stop_reason` 打出来。

**3. 把 `extract_text` 里的过滤去掉，改成 `b.get("text", b.get("thinking", ""))`。**

→ 实测（问「为什么天空是蓝色的？一句话回答」）：

```
用户现在需要一句话回答天空为什么蓝，天空呈蓝色的一句话解释已由我拟定：太阳光射入地球大气层时，
波长较短的蓝光易被大气分子散射……太阳光穿过地球大气层时，波长较短的蓝光更容易被空气分子散射，
加上人眼对蓝光的感知强于散射更强的紫光，因此天空看起来呈蓝色。
```

思考过程和正文**黏在一起了**，因为 `"".join` 中间没有分隔符。这就是为什么过滤是必要的：不做区分，你分不清哪句是「它想的」、哪句是「它说的」。
