# V0：一次对话，看清 HTTP 往返

## 1. 这一版做了什么

一句话发给模型，模型回一句。**没有记忆，没有工具，没有循环**。

```powershell
uv run python src/v0_chat.py "用一句话介绍你自己"
```

真实输出：

```
我是字节跳动开发的人工智能，可为你提供信息查询、问题解答、创意生成等各类实用帮助。

[用量] 输入 54 / 输出 154 tokens
```

代码一共 77 行（含空行和注释），纯代码约 40 行。

## 2. 代码逐块讲

### 顶部的三行 `reconfigure`（第 8–11 行）

```python
if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
    sys.stderr.reconfigure(encoding="utf-8", errors="replace")
```

**去掉会怎样**：模型回你的中文在 Windows 上可能抛 `UnicodeEncodeError`，或者显示成 `????`。

**为什么需要**：Java 里 `System.out` 默认就是系统编码，编码问题由 JVM 启动参数处理；Python 默认跟随系统 locale，Windows 中文环境就是 GBK。这行是告诉 Python「不管系统怎么设置，我都按 UTF-8 输出」。

> 附带的坑：如果你的终端显示的仍然是乱码（比如 `杈撳嚭` 这种），那是**终端**在用 GBK 解码 UTF-8 字节，不是 Python 的问题。在 PowerShell 里先执行：
> ```powershell
> [Console]::OutputEncoding = [Text.Encoding]::UTF8
> ```
> 就正常了。

### 常量区（第 13–17 行）

```python
API_URL = "https://ark.cn-beijing.volces.com/api/coding/v1/messages"
MODEL = "doubao-seed-2-1-pro"
SYSTEM_PROMPT = "你是一个简洁的中文助手，回答控制在三句话以内。"
MAX_TOKENS = 512
```

**去掉会怎样**：URL 写死在各处，改一次要改五遍。

**`SYSTEM_PROMPT` 是什么**：模型收到的「角色设定」，它在对话之外先于你的问题生效。Java 类比：像 Servlet 的 `init` 参数——不是你每次请求传的，而是框架在每次处理前先塞进去的。它影响语气和长度，但**不影响模型有没有记忆**（这是 V0 最容易被误解的一点）。

### `build_payload`（第 20–27 行）

```python
return {
    "model": MODEL,
    "max_tokens": MAX_TOKENS,
    "system": SYSTEM_PROMPT,
    "messages": [{"role": "user", "content": user_text}],
}
```

**去掉会怎样**：没有请求体，`requests.post` 只能发空请求。

**`messages` 为什么是数组**：因为真实对话有多个角色轮流说话。哪怕现在只有一句，格式也必须是数组——这个形状在 V2 会直接决定你怎么实现多轮。

Java 类比：`List<Message>`，其中 `Message` 就是 `{role, content}` 两个字段的 POJO。

### `extract_text`（第 30–33 行）

```python
blocks = data.get("content", [])
return "".join(b.get("text", "") for b in blocks if b.get("type") == "text")
```

**去掉会怎样**：你只能打印整个 JSON，看不到干净的回复。

**为什么不能直接取 `data["content"]`**：响应里的 `content` **不是一个字符串，而是一个「块」的数组**。这一点极其重要——现在只有 `text` 块，但 V1 加工具后，会出现 `tool_use` 块；不加过滤就会把参数字典也拼进回复里。

### `chat`（第 36–73 行）

四件事按顺序做：

1. **读 key**：`os.environ.get("ARK_API_KEY")`，为空就打印中文提示并 `exit(1)`。
   **为什么不用 `os.environ[...]`**：那样 key 缺失时会抛 `KeyError` 和一堆堆栈，你看不出「是没设环境变量」还是「代码有 bug」。
2. **发请求**：注意请求头是 `x-api-key`，**不是** `Authorization: Bearer`。
   **去掉会怎样**：401。这是火山方舟 Coding Plan 端点跟 OpenAI 风格最直观的差别。
3. **判断状态码**：`if resp.status_code != 200` 时把 `resp.text` 原样打出来。
   **为什么不用 `raise_for_status()`**：服务端返回的 `error.code`（比如 `InvalidEndpointOrModel.NotFound`）才是真正的诊断信息，`raise_for_status()` 会把它埋在异常里。
4. **打印用量**：`usage` 里的 `input_tokens` / `output_tokens`。
   **为什么关心它**：这就是你付钱的地方，也是后面判断「上下文是不是快爆了」的唯一依据。

**`try/except` 是计划之外的**：实测时有一次请求卡了 60 秒，直接甩出 20 行 traceback。加了这三行后，超时会打印「网络请求失败：…重跑一次通常就好」。这属于「出问题要能定位」，所以留在 V0 了。

### `__main__`（第 76–77 行）

```python
chat(sys.argv[1] if len(sys.argv) > 1 else DEFAULT_QUESTION)
```

**为什么用 `sys.argv[1]` 而不是 `input()`**：命令行参数能让你把一句话整体传进去（带空格也不会被切）。`input()` 留到 V2 的交互式 REPL 再上。

## 3. 值得记住的三件事

### ① 模型没有记忆——这是 V0 唯一真正要理解的事

连续跑两次：

```powershell
uv run python src/v0_chat.py "记住我叫阿杰"
# 好的，我已经记住你叫阿杰啦，之后都会这么称呼你哦。

uv run python src/v0_chat.py "我叫什么名字"
# 我暂时还不知道你的名字哦，你可以告诉我你的称呼呀。
```

第一次它说「记住了」，第二次它不知道你叫什么。

**不是它撒谎**，而是「记住」只发生在**那一次请求内部**。每次运行都是一次全新的、无状态的调用——你的程序里没有把上一次的对话存到任何地方，模型那边也不会替你存。

Java 类比：像每次请求都 new 一个新的、没有任何字段的 Service 实例。**记忆必须由你的代码提供**，这就是 V2 要写的东西：把历史 `messages` 攒起来，每次完整发过去。

### ② 响应是「块」的数组，不是字符串

现在你看到的是：

```json
{"type": "text", "text": "..."}
```

V1 你会看到多出来：

```json
{"type": "tool_use", "id": "call_xxx", "name": "list_dir", "input": {"path": "."}}
```

以及一个 `thinking` 块。所以过滤 `type` 这个习惯，从第一天就要养成。

### ③ 认证方式跟「主流」不一样

| | 火山方舟 Coding Plan | OpenAI |
|---|---|---|
| 地址 | `/api/coding/v1/messages` | `/v1/chat/completions` |
| 认证头 | `x-api-key` | `Authorization: Bearer` |
| 请求体 | `messages` + `system`（顶层） | `messages`（system 也是其中一条） |

**概念完全一样，只是字段名不同**。看懂这一版之后，换任何厂商只是改这几行。

## 4. 改一改试试（自愿，但强烈建议做前两个）

1. **把 `MODEL` 换成 `"claude-sonnet-4-5"`**，别的都不动，看是否还能跑。
   → 你会看到：**照样能跑**。因为服务端把 `claude-sonnet-4-5` 这个别名路由到了 `doubao-seed-2-1-turbo`。想看真实路由结果，在 `chat()` 里加一行 `print(data["model"])`。这跟 V1 会遇到的「工具名写错」是同一类问题：**名字对不上时，你要先确认是「真的不存在」还是「别名指到别处」**。

2. **把 `MAX_TOKENS` 改成 `16`**，再问一句长问题。
   → 你会看到回复被硬切在中途（实测：「杭州是浙江省省会，坐落于钱塘江下游、京杭大运河南端，」）。注意脚本**照样正常打印，没有任何警告**——因为 `extract_text` 拿到了非空字符串。**「有内容」不等于「完整」**，这个区别只有 `stop_reason`（值为 `max_tokens`）能告诉你。V2 会把 `stop_reason` 打出来。

3. **删掉 `extract_text` 里的 `if b.get("type") == "text"` 过滤**，改成 `b.get("text", b.get("thinking", ""))`。
   → 你会看到模型的思考过程也被打印出来了。这就是为什么过滤是必要的。
